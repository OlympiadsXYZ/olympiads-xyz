# Схема на архива (Archive Schema)

Канонична схема за целия архив на Olympiads XYZ. Тя управлява **всеки запис в
`archive-catalog/*.json`** и **всяко бъдещо вкарване на нови файлове**.

- Машинна дефиниция: [`archive-catalog/schema.json`](../archive-catalog/schema.json) (JSON Schema draft 2020-12)
- Валидатор: `node scripts/validate-catalog.mjs` (без npm зависимости, връща код 1 при нарушение)
- Етикети за UI: `src/archive/labels.ts`

> **Имената на полетата и стойностите в речниците са латински** (`problems`,
> `data-analysis`, `theory`), точно както ги ползва кодът. Български текст има
> само в `title` и в човешките етикети от `labels.ts`. Текущите данни смесват
> български и латински стойности — раздел „Таблици за преобразуване“ дава по
> едно канонично съответствие за **всяка** наблюдавана стойност.

---

## 1. Форма на файла

Всеки `archive-catalog/*.json` е **масив от записи**. Няма обвиващ обект, няма
метаданни на ниво файл. Разделянето по файлове е чисто организационно —
каталозите се сливат при билда, така че `id` и `file` трябва да са уникални
**през всички файлове**, не само в рамките на един.

```json
[
  {
    "id": "phys-ipho-2019-theory-problems",
    "subject": "physics",
    "kind": "competition",
    "competition": "IPhO",
    "year": 2019,
    "round": "theory",
    "group": null,
    "type": "problems",
    "lang": "en",
    "title": "IPhO 2019 · Теоретичен тур · Условия",
    "file": "Физика/Състезания/IPhO/2019/Theory/problems.pdf",
    "size": 1048576,
    "sourceUrl": "https://www.ipho2019.il/theory.pdf",
    "source": "Google Drive",
    "addedAt": "2026-08-30"
  }
]
```

## 2. Полета

### 2.1 Задължителни ключове

Тези дванадесет ключа трябва да **присъстват във всеки запис**. Част от тях
допускат `null` — но ключът се изписва изрично, за да няма разлика между „няма
стойност“ и „забравено поле“.

| Поле | Тип | `null`? | Описание |
|---|---|---|---|
| `id` | string | не | Стабилен уникален идентификатор. `^[a-z0-9]+(-[a-z0-9]+)*$` — само малки латински букви, цифри и единични тирета; без водещо/затварящо тире. Не се сменя след публикуване (влиза в URL и в отметките на потребителите). |
| `subject` | string | не | Научна област. Контролиран речник §3.1. |
| `kind` | string | не | Какъв е документът на ниво архив. Контролиран речник §3.2. |
| `competition` | string \| null | да | Код на състезанието от `COMPETITION_META` в `src/archive/labels.ts`. `null` за всичко извън състезание. Книга или помагало **може** да носи код (сборник със задачи от IPhO стои и на рафта, и на страницата на IPhO). §3.3. |
| `year` | integer \| null | да | Година на провеждане/издаване, 1950–2100. `null`, ако е недатирано. За учебни години („2012/13“) се записва **началната** година. |
| `round` | string \| null | да | Етап или тур. Контролиран речник §3.4. |
| `group` | string \| null | да | Класова група. Контролиран речник §3.5. |
| `type` | string \| null | да | Вид на документа. Контролиран речник §3.6. |
| `lang` | string | не | ISO 639-1 код на езика **на съдържанието**, не на заглавието. §3.7. |
| `title` | string | не | Човешко заглавие, на български. 2–300 знака, не само празни знаци. Латинските имена на международни състезания се запазват (`IPhO 2019 · …`). |
| `file` | string | не | Ключ в кофата, релативен, без водеща наклонена черта, без `//`. Първата папка трябва да съответства на `subject` (§3.8). Уникален през целия каталог. |
| `size` | integer | не | Размер в байтове, ≥ 1. Взима се от листинга на кофата, не се въвежда на ръка. |

### 2.2 Незадължителни ключове

| Поле | Тип | Описание |
|---|---|---|
| `sourceUrl` | string | Оригинален източник. Задължително `https://`. Добавя се, когато файлът е свален от публичен сайт — служи за проверка и за препубликуване. |
| `source` | string | Провенанс с човешки думи, когато няма URL. Наблюдавани: `Stefan Ivanov (Mega)`, `Google Drive`. |
| `addedAt` | string | Дата на добавяне, `YYYY-MM-DD`. Пише се от ingest скрипта. |
| `note` | string | Свободна бележка за куратора (варианти на едно издание, дефекти, спорна класификация, „истинският материал липсва в архива“ — D5, „решението липсва“ — D9). 2–1000 знака. |
| `hidden` | boolean | `true` = записът **не се показва и не се брои** в сайта (`loadCatalog` го пропуска). Ползва се за байт-идентични дубликати, плейсхолдъри и боклук; файлът остава в кофата — нищо не се трие (D1). Обратимо: махането на флага връща записа. |
| `duplicateOf` | string | `id` на каноничния запис, чийто файл този запис дублира (D3/D4). Същият формат като `id`. Изисква `hidden: true`. |
| `unparsed` | boolean | Наследен флаг: метаданните са изведени от името на файла, без да са проверени. Означава „за преглед“, не „грешно“. |

### 2.3 Забранени ключове

`additionalProperties: false` — **всеки друг ключ е нарушение.** В частност
`_catalogFile` се добавя от одит скриптовете при сливане и никога не бива да
се записва в самите каталози.

## 3. Контролирани речници

### 3.1 `subject`

Едно към едно с кореновите папки в кофата. Затворен речник.

| Канонично | Папка | Записи |
|---|---|---|
| `physics` | `Физика/` | 4195 |
| `astronomy` | `Астрономия/` | 2926 |
| `chemistry` | `Химия/` | 252 |
| `geography` | `География/` | 124 |
| `mathematics` | `Математика/` | 26 |
| `informatics` | `Информатика/` | 8 |

**Преобразуване:** `math` → **`mathematics`** (16 записа). Пълната дума е
каноничната — съгласувано с `physics`, `chemistry`, `informatics`.

### 3.2 `kind`

Какъв е документът **на ниво архив** — на кой рафт стои.

| Канонично | Значение |
|---|---|
| `competition` | Изпитни материали от състезание: условия, решения, критерии, данни, отговори. |
| `book` | Издадена книга, учебник, сборник. |
| `handout` | Учебен материал, семинар, лекция, домашни — неиздадено. |
| `syllabus` | Регламент, програма, силабус, официални правила на състезание. |
| `results` | Самостоятелни протоколи, класирания, състави на отбори. |
| `misc` | Всичко останало: училищни записки, снимки, работни таблици, инструменти. |

> **Важно:** `kind` **не** е тестът „принадлежи ли на състезание“. Този тест е
> `competition !== null`. Регламентът на НОФ е `kind: "syllabus"`,
> `competition: "NOF"` — намира се и на страницата на НОФ, и в рафта с
> регламенти.

**Ред на приоритет при класифициране** (първото, което съвпада, печели):
`book` → `handout` → `syllabus` → `results` → `competition` → `misc`.

**Преобразуване:**

| Наблюдавано | Канонично | Записи | Бележка |
|---|---|---|---|
| `competition` | `competition` | 7252 | |
| `handout` | `handout` | 143 | |
| `book` | `book` | 123 | |
| `school` | `misc` | 10 | Училищни `.note` записки по математика. |
| `other` | `misc` | 2 | Преименуване, за да не се бърка с `type: "other"`. |
| *(липсва)* | — | 1 | `rem26-slobodyanyuk-t7-variant` няма `kind`; трябва `book`. |

`syllabus` и `results` са нови кодове и **все още имат нула записа** — те
събират материал, който днес е сгрешено маркиран: 43 записа с
`type: "Официални документи"` (кодекси, регламенти, програми) и 253 записа с
`type: "Резултати"/"results"`, които са самостоятелни протоколи. Пре-класификацията
им е отделна задача; схемата вече ги допуска.

### 3.3 `competition`

**Отворен** речник — нови състезания се добавят постоянно. Схемата налага само
формата: `^[A-Za-zА-Яа-яЁё0-9][A-Za-zА-Яа-яЁё0-9.\-]*$` — **без интервали**.
Регистърът на познатите кодове е `COMPETITION_META` в `src/archive/labels.ts`;
код извън него работи (UI прави транслитерация), но трябва да се добави там,
за да получи българско име.

Кодовете на международните състезания са латински съкращения (`IPhO`, `IOAA`,
`APhO`, `IZhO`, `EuPhO`, `IChO`, `iGeo`, `NAO`, `NOF`, `ESF`, `PSF`, `NOH` …).
Няколко национални са с кирилски кодове (`Всерусийска`, `Московска`,
`Балкански`, `ПУ`) — те са в регистъра и остават валидни.

**Преобразуване** (31 записа с интервали или сгрешен код):

| Наблюдавано | Канонично | Записи |
|---|---|---|
| `Online Physics Brawl` | `OPB` | 5 |
| `Олимпиада на мегаполисите` | `IOM` | 25 |
| `Московска олимпиада по физика` | `Московска` | 1 |
| `Книги` | `null` (+ `kind: "book"`) | 1 |

Два двойки кодове изглеждат дублирани, но **не са** и не бива да се сливат:
`Всерусийска` (физика) ↔ `VsOA-ru` (астрономия); `Балкански`
(Турнир „Минко Балкански“, 107 записа) ↔ `Balkan` (Балканска олимпиада по
физика, 33 записа). И двата от втората двойка се нуждаят от запис в
`COMPETITION_META`, за да не се четат като едно и също.

### 3.4 `round`

олимпиада) и **турове** (частта на изпита). Едно състезание ползва едното или
другото; там, където има и двете (НОА: „IV кръг, теоретичен тур“), етапът е в
`round`, а турът остава в `title` до отделна миграция.

  дублират `competition: "ESF"` / `"PSF"` — есенното и пролетното национално
  състезание са отделни състезания, не кръгове. Информация не се губи.

  олимпиада; `type: "problems"` вече казва каквото трябва.
- **`Финален кръг`, `IV Подбор` → `IV`.** Проверено срещу данните: същите
  състезания ползват и `IV` за същия етап (Всерусийска има и `IV`, и
  `Финален кръг`; НОФ има и `IV`, и `IV Подбор`).

**Известно застъпване за нататък:** при състезанията от системата на ВсОШ
(`Всерусийска`, `VsOA-ru`, `Struve`) „регионален етап“ е трети етап, така че
`regional` и `III` описват едно и също. `regional` се пази за състезания без
номерирани етапи; уеднаквяването на ВсОШ към `III` е отделна миграция.

### 3.5 `group`

Класова група. Две форми:

**Класове** — само цифри, без думата „клас“, диапазонът с тире във възходящ
ред, без водеща нула: `^(1[0-2]|[1-9])(-(1[0-2]|[1-9]))?$`.
Примери: `9`, `11`, `7-8`, `11-12`, `1-11`.

**Именовани групи** — когато състезанието дели по група, а не по клас:

| Канонично | Етикет | Използва се от |
|---|---|---|
| `ML` | Младша | НОА, IZhO |
| `ST` | Старша | НОА, IZhO |
| `SP` | Спец. група | НЕСФ, НПСФ |
| `alpha` | Група α | IAO, APAO |
| `beta` | Група β | IAO, APAO |

**Преобразуване:** маха се суфиксът ` клас` и водещите нули —
`10 клас` → `10`, `11-12 клас` → `11-12`, `08-09 клас` → `8-9`,
`младша група` → `ML`, `старша група` → `ST` (621 записа общо).

> **Внимание — `ST` е двусмислено в текущите данни.** При НОА и IZhO означава
> „старша група“; при НЕСФ и НПСФ означава „**спец. група**“ (виж заглавията:
> „Пролетно национално състезание 2023 – спец. група“). Затова
> преобразуването е **зависимо от състезанието**:
>
> | Наблюдавано | `competition` | Канонично | Записи |
> |---|---|---|---|
> | `ST` | `NAO`, `IZhO` | `ST` | 90 |
> | `ST` | `ESF`, `PSF` | `SP` | 109 |

### 3.7 `lang`

ISO 639-1, малки букви. Езикът **на съдържанието на файла**, не на заглавието
в каталога. Затворен речник от наблюдаваното:

`bg` (2631) · `en` (3033) · `ru` (1721) · `fr` (99) · `sr` (18) · `cs` (11) ·
`kk` (9) · `ro` (8) · `mk` (1)

Нов език се добавя в `enum` в `schema.json` **и** в `LANG_LABELS` в
`src/archive/labels.ts` едновременно.

### 3.8 `file` — ключ в кофата

- Релативен път, без водеща `/`, без `//`, без затваряща `/`.
- Първата папка се определя от `subject` и се проверява от схемата:
  `physics → Физика/`, `astronomy → Астрономия/`, `chemistry → Химия/`,
  `geography → География/`, `mathematics → Математика/`,
  `informatics → Информатика/`.
- Уникален през целия каталог. Два записа за един файл са дубликат, не два
  документа.
- Позволени разширения: `pdf`, `djvu`, `doc`, `docx`, `rtf`, `txt`, `html`,
  `note`, `xls`, `xlsx`, `csv`, `ppt`, `pptx`, `ppsx`, `nb`, `jpg`, `jpeg`,
  `png`, `gif`, `mp4`, `wmv`, `zip`, `rar`, `exe`, `linux`, `macos`.

**Изпълними файлове (D8).** Програми и симулатори към експериментални/практически
кръгове (`gmcounter.{exe,linux,macOS}` на НОФ IV 2022, шестте програми на EuPhO
2021) са състезателни материали и остават видими с `kind: "misc"`,
`type: "data"` и бележка „изпълним файл (PE/ELF/Mach-O)“; `entryExt()` ги
показва с код `exe` („Изпълним файл“). Файл **без разширение** се допуска
**само** при `kind: "misc"` и `type: "data"` (правило 9 в §4). Изпълним файл,
който не е състезателен материал (`География/Geografia.exe`), е `hidden`.

## 4. Правила за съгласуваност

Схемата налага и следните междуполеви правила:

1. `kind: "competition"` ⇒ `competition` не е `null`.
2. `kind: "book"` или `"handout"` ⇒ `round: null`. **`competition` е позволено**
   (§3.2: тестът за принадлежност към състезание е `competition !== null`, не
   `kind`) — сборниците с олимпиадни задачи (IPhO 1967–1999, Всесъюзна/
   Всерусийска, Московска, `astro-ioaa-book`) са книги, които се виждат и на
   страницата на състезанието. До 4 септ. 2026 правилото изискваше и
   `competition: null`.
3. `competition: null` ⇒ `round: null` (кръг без състезание няма смисъл).
4. `type: "book"` ⇒ `kind: "book"`; `type: "handout"` ⇒ `kind: "handout"`.
5. `kind: "results"` ⇒ `type: "results"`.
6. `kind: "syllabus"` ⇒ `type` е `official` или `other`.
7. Кореновата папка на `file` съответства на `subject` (§3.8).
8. `duplicateOf` ⇒ `hidden: true` (скрит дубликат, не втори видим запис).
9. `file` без разширение ⇒ `kind: "misc"` и `type: "data"` (изпълним файл, D8).

Извън JSON Schema валидаторът проверява още: уникалност на `id`, уникалност на
`file`, позволените разширения и — с `--bucket` — че всеки `file` наистина
съществува в кофата. Скритите записи (`hidden: true`) се валидират като всички
останали — те са част от каталога, само сайтът ги пропуска.

**Патчове.** Корекции по решенията от `docs/Archive-Decisions-2026-09.md` се
прилагат с `node scripts/apply-catalog-patches.mjs [--dir tmp/archive-fix]
[--dry-run]`: патч-файловете (`*.patch.json`, `[{id, set:{…}, evidence,
decision}]`) се прилагат по азбучен ред на файла; патч с непознат `id` или
стойност извън речниците се отказва цял; `set.id_new` преименува `id` само ако
нищо друго не го реферира. Скриптът е идемпотентен.

## 6. Какво трябва да се промени в кода

Каноничните речници въвеждат кодове, които `src/archive` още не познава:

- `src/archive/catalog-node.ts` — типът `kind` е
  `'competition' | 'book' | 'handout' | 'other'`; да стане
  `'competition' | 'book' | 'handout' | 'syllabus' | 'results' | 'misc'`, а
  групирането в `groupCatalog` да третира `syllabus`/`results`/`misc` явно,
  за да не падат в `uncategorized`.
- `src/archive/labels.ts`:
  - `ROUND_LABELS` / `ROUND_ORDER` — да се добавят `camp` („Учебен сбор“),
    `day-1`/`day-2`/`day-3` („Ден 1/2/3“); `regional` да смени етикета си от
    „Областен кръг“ на „Регионален кръг“, за да не се бърка с `II`.
  - `TYPE_LABELS` / `TYPE_ORDER` — да се добавят `answer-sheet`, `criteria`,
    `instructions`, `official`.
  - `groupLabel` — да се добави `SP → 'Спец. група'`.
- `COMPETITION_META` — да получи записи за кодовете, които днес нямат
  българско име: `BelPhO`, `ISPhO`, `NBPhO`, `OPhO`, `WoPhO`, `GPhO`, `InPhO`,
  `FYKOS`, `Samara`, `Struve`, `IOAA-Jr`, `BAAO`, `USAAAO`, `OWAO`, `O3A2`,
  `HOOS`, `Serbia`, `Balkan`, `China`, `Estonia`, `Ibero-American`.

## 7. Ред на миграцията

1. Скрипт за нормализация, който прилага таблиците от §3 (те са пълни —
   очаква се 0 непокрити стойности).
2. Ръчни решения: липсващият `kind`, трите `id` със затварящо тире, десетте
   `type: "handout"` при книги, единайсетте изпълними файла.
3. Пре-класификация на `kind` към `syllabus`/`results` за 43-те „Официални
   документи“ и самостоятелните протоколи.
4. Разчистване на 1018-те `type: "other"` — най-голямата останала работа.
5. `validate-catalog.mjs` да влезе в pre-commit hook и в CI.
