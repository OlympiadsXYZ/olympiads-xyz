## 1. What the project is

Olympiads XYZ is the revival of Margulan's Bulgarian olympiad-preparation site (physics and astronomy first),
a Gatsby 4 fork of the USACO Guide. Three pillars:

1. **Наръчник** (handbook): Ниво → Секция → Категория → Модул. The five Drive docs are the spec (`docs/Structure.md`);
   the Kinematics category is the calibrated exemplar. Modules are authored one at a time to `docs/Module-Standard.md`
   with human review; bulk AI modules were rejected as slop (rules in §9).
2. **Архив**: 7,531 catalogued competition PDFs in the Cloudflare R2 bucket `olympiads-archive`, served through the
   site's `/archive/...` proxy. Catalogue in `archive-catalog/*.json`; decisions in `docs/Archive-Decisions-2026-09.md`.
3. **Задачи**: every problem from those PDFs becomes a page with the verbatim statement, figures, answers and the
   official solution, browsable by competition / year / grade (file-tree sidebar) with a compare-with-PDF panel.

## 4. Pipeline v2 (`scripts/tx/`) — how transcription works now

Decided on 2026-09-06 after the Codex review; replaces the two-Opus-agents-per-paper workflows, which Margulan stopped as
too wasteful. Documented in `docs/Transcription-Pipeline.md`; decisions D-P1…D-P9 in `docs/Problems-Decisions-2026-09.md`.

```
prepare.mjs <id> [--problems k --solutions k]   rclone → tmp/tx/<id>/src/*.pdf, pdftoppm 160 dpi → pages/, pdftotext → text/, manifest.json (idempotent by sha256)
transcribe.mjs <id> --provider zai --model glm-5.3-flash --stage reader [--window-pages 8]     API reader (windows for long papers)
task.mjs <id> --stage reader|checker|adjudicator --out <file> [--model <label>] [--candidate f]  prints a self-contained task for a Claude agent
validate.mjs <cand.json> --paper-id <id> --manifest tmp/tx/<id>/manifest.json                   schema, ids, points, KaTeX, boxes, spans
figures.mjs <id> <cand.json> [--dry-run]     pdfcrop → tmp/tx/<id>/figs/<candidate>/…, writes <cand>.figs.json; without --dry-run uploads to R2 (only when absent)
transcribe.mjs <id> --provider zai --model glm-5.3-flash --stage checker --candidate <cand>.figs.json --out tmp/tx/<id>/checks/<checker>__for-<candidate>.json
receipt.mjs <id> --candidate <cand>.figs.json --defects <check.json> --reviewer zai:glm-5.3-flash:<requestId> --prompt-version v1   → tmp/tx/<id>/receipt.json
promote.mjs <id> --candidate <cand>.figs.json --receipt tmp/tx/<id>/receipt.json [--replace]   → content/problems/…, content/problem-receipts/<id>.json, publication.mjs approve
run.mjs <id> --reader zai:glm-5.3-flash --checker agent:haiku [--continue]   state machine over the chain (tmp/tx/jobs.json); an agent: stage prints its task and exits 2
repair.mjs, assemble.mjs, bench.mjs, bench-status.mjs, evidence.mjs, backlog.mjs; prompts/v1/{reader,checker,adjudicator}.md (sha recorded in every output)
```

Naming conventions the scripts rely on: candidates are `tmp/tx/<id>/candidates/<provider>__<model>.json`
(`zai__glm-5.3-flash.json`, `agent__haiku.json`, `agent__sonnet.json`); the checker's default output is
`checks/<provider>__<model>.json`, so always pass `--out …__for-<candidate>.json` when more than one candidate is checked;
`bench-status.mjs` hard-codes those three reader names.

Measured facts for Z.ai GLM-5.3-Flash (`tmp/tx-provider-notes.md`): endpoint `https://api.z.ai/api/paas/v4/chat/completions`;
thinking cannot be disabled, but top-level `reasoning_effort: "low"` gives 0 reasoning tokens; `max_tokens` ≤ 131072; request
cap 20 MB (the adapter re-encodes pages as JPEG when over); ~3,230 prompt tokens per 160-dpi page; ~1.5 ¢ per paper at list
price; 1.5–9.5 min per paper. Margulan bought the 100M-token trial bundle (price per him, not recorded). Usage as of the bundle
(last call 2026-09-08): 88 successful calls, 4.42M tokens, $0.83 at list price; recompute with
`jq -s '[.[]|select(.ok!=false)]|{calls:length,tokens:(map(.inputTokens+.outputTokens)|add),usd:(map(.costUsd)|add)}' tmp/tx/runs.jsonl`.

Fixes that landed during the benchmark (all committed): window-merge deduplication and `lang` default; null-field sanitiser;
JSON escape repair for a lone LaTeX backslash; per-candidate crop folders; numbering rule ("Задача 1.1/1.2 are parts, not
problems"); 20-minute fetch timeouts with retries; checker outputs bound to the candidate bytes by hash and receipts that
reject incomplete coverage (Codex, 2026-09-08).

## 8. How to ship content safely

1. Get a passing receipt: `node scripts/tx/run.mjs <id> --reader zai:glm-5.3-flash --checker agent:haiku` (an `agent:` stage
   prints its task and exits 2; run the agent, then `run.mjs <id> --continue`), or by hand: reader → `validate.mjs` →
   `figures.mjs <id> cand.json` (real upload) → checker → `receipt.mjs` → `promote.mjs`. `promote.mjs` writes
   `content/problems/…/<id>.json`, stores the receipt under `content/problem-receipts/`, and runs `publication.mjs approve`;
   `node scripts/publication.mjs status` shows the ledger.
2. `node scripts/normalise-papers.mjs && node scripts/problems-to-site.mjs && node scripts/check-mdx.mjs && node --test scripts/tests/problems.test.mjs scripts/tests/tx.test.mjs && python3 scripts/validate-papers.py`
3. Commit the paper JSON, `content/problem-receipts/`, `content/problem-publication.json`, the regenerated `solutions/**.mdx`,
   `content/extraProblems.json`, `content/problem-generated.json`, `content/problem-routes.json`; push `master`.
4. `gh run watch` (or `gh run list --workflow deploy-prebuilt.yml`). A run still going at 10 minutes is abnormal: look at
   `gh run view <id> --log-failed`, do not wait for the timeout. Vercel publishes `deploy` within a minute of a green run.
5. Verify in a real browser, never by HTTP 200 alone: `/problems-data/index.json` entry count, one old URL, one new URL,
   a page with figures, the verification notice, and the compare panel. The PDF is the ground truth for any doubt.

Never build Gatsby on the 8.6 GB Mac (it reboots). On the PC a local `gatsby build` is worth trying only with ≥ 16 GB RAM and
`GATSBY_ARCHIVE_ENABLED` unset; the Actions runner is the reference build either way.

## 10. Adjudicator subagent brief

Give one Fable-class subagent per paper the printed output of `task.mjs --stage adjudicator` (§5 step 2): it lists the page
images to Read in order, each candidate's sanitised view and crop PNGs, every check, and the optional non-gold reference.
Require: a gold JSON that passes `validate.mjs`, built from the candidate closest to the pages and corrected field by field
(verbatim text, LaTeX, tables, points, figure boxes in permille, sourceSpans, solutions on the right problem, source errors
preserved and noted); the adjudication JSON in the shape `prompts/v1/adjudicator.md` specifies, with every candidate's defects
(path, severity, kind, printed-vs-candidate) and a true/false-positive verdict for every checker finding; escalations for
anything unreadable; no edits to candidates or checks; no gatsby; no git. Ask it to report back which candidate it started
from, per-candidate critical/major/minor counts, checker true/false positives, escalations, and whether the gold validated.
