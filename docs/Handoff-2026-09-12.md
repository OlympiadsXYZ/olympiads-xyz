## 1. What the project is

Olympiads XYZ is the revival of Margulan's Bulgarian olympiad-preparation site (physics and astronomy first),
a Gatsby 4 fork of the USACO Guide. Three pillars:

1. **Наръчник** (handbook): Ниво → Секция → Категория → Модул. The five Drive docs are the spec; the Kinematics
   category is the calibrated exemplar. Modules are authored one at a time with human review; bulk AI modules
   were rejected as slop (see the rules in §9).
2. **Архив**: 7,531 catalogued competition PDFs in the Cloudflare R2 bucket `olympiads-archive`, served through the
   site's `/archive/...` proxy. Catalogue in `archive-catalog/*.json`; decisions in `docs/Archive-Decisions-2026-09.md`.
3. **Задачи**: every problem from those PDFs becomes a page with the verbatim statement, figures, answers and the
   official solution, browsable by competition / year / grade (file-tree sidebar) with a compare-with-PDF panel.

## 4. Pipeline v2 (`scripts/tx/`) — how transcription works now

Decided on 2026-09-06 after the Codex review; replaces the two-Opus-agents-per-paper workflows, which Margulan stopped as
too wasteful. Documented in `docs/Transcription-Pipeline.md`; decisions D-P1…D-P9 in `docs/Problems-Decisions-2026-09.md`.

```
prepare.mjs <paperId>            rclone → tmp/tx/<id>/src/*.pdf, pdftoppm 160 dpi → pages/, pdftotext → text/, manifest.json
transcribe.mjs <id> --provider zai --model glm-5.3-flash --stage reader   (API reader; --window-pages 8 for long papers)
task.mjs <id> --stage reader|checker|adjudicator --out …                  (prints a self-contained task for a Claude agent)
validate.mjs cand.json --paper-id <id> --manifest …                        (schema, ids, points, KaTeX, boxes, spans)
figures.mjs <id> cand.json [--dry-run]                                     (pdfcrop → figs/<candidate>/…, upload only when absent)
transcribe.mjs … --stage checker --candidate cand.figs.json               (independent checker, sees pages + crops + sanitised view)
receipt.mjs / promote.mjs                                                  (receipt bound to exact bytes → content/problems + ledger approve)
repair.mjs, assemble.mjs, run.mjs (state machine), bench.mjs, bench-status.mjs, evidence.mjs
prompts/v1/{reader,checker,adjudicator}.md                                 (versioned; sha recorded in every output)
```

Measured facts for Z.ai GLM-5.3-Flash (`tmp/tx-provider-notes.md` after restore): endpoint
`https://api.z.ai/api/paas/v4/chat/completions`, thinking cannot be disabled but top-level `reasoning_effort: "low"`
gives 0 reasoning tokens, `max_tokens` ≤ 131072, request cap 20 MB (the adapter re-encodes pages as JPEG when over),
~3,230 prompt tokens per 160-dpi page, ~1.5 ¢ per paper at list price, 2–9 min per paper. The 100M-token trial bundle
Margulan bought ($9.90) has used about 4.4M tokens so far (89 recorded calls, $0.83 at list price); check the balance in the Z.ai console.

Fixes that landed during the benchmark (all committed): window merge deduplication and `lang` default; null-field
sanitiser; JSON escape repair for a lone LaTeX backslash; per-candidate crop folders; numbering rule
("Задача 1.1/1.2 are parts, not problems"); 20-minute fetch timeouts with retries; checker outputs bound to the
candidate bytes by hash (Codex, 2026-09-08); receipts that reject incomplete coverage.

Current verdict (7 usable adjudicated papers; treat as workflow comparison, not model ability): **no reader passed any
paper outright**. Haiku 7/7 with critical defects (omitted tables, fabricated passages on old scans), GLM 7/7 (mostly
figure boxes that land on body text; text otherwise near-verbatim), Sonnet 4/6 (closest; mostly crop and silent-typo-fix
issues). Checkers: Haiku 20 true / 3 false findings, 1 false pass; GLM 43 true / 8 false findings, 5 false passes.
Sample adjudication cost: ~0.44M tokens and 40 min of one Fable agent per paper.

Interpretation so far: the cheap readers are usable only with the repair loop plus a strong checker; figure localisation is
the weak spot for every cheap model; Sonnet 5 is the best cheap reader on quality, GLM the cheapest by far. The final
decision needs the remaining adjudications.

## 8. How to ship content safely

1. Paper JSON into `content/problems/<subject>/<COMP>/<year>/<paperId>.json` (via `promote.mjs`, which also writes the receipt
   and `publication.mjs approve`).
2. `node scripts/normalise-papers.mjs && node scripts/problems-to-site.mjs && node scripts/check-mdx.mjs && node --test scripts/tests/problems.test.mjs scripts/tests/tx.test.mjs && python3 scripts/validate-papers.py`
3. Commit source JSON + regenerated MDX/index/manifest/routes; push `master`.
4. Watch `gh run list --workflow deploy-prebuilt.yml`; Vercel publishes `deploy` within a minute of a green run.
5. Verify in a real browser (not just HTTP 200): `/problems-data/index.json` count, one old URL, one new URL, a page with
   figures, the verification notice. Ground truth for any doubt is the PDF itself.

Never build Gatsby on the 8.6 GB Mac (it reboots). On the PC, a local `gatsby build` is only worth trying with ≥ 16 GB RAM and
`GATSBY_ARCHIVE_ENABLED` unset; the Actions runner is the reference build either way.

## 9. Margulan's standing rules (from memory on the Mac)

- Terse, hands-on; decide routine things yourself and record the decision (decision docs); ask only when readings differ materially.
- Never bulk-generate handbook modules; one calibrated exemplar, human review before publishing.
- Never Opus/Fable for bulk transcription again; cheap readers + scripted pipeline; Fable only to adjudicate.
- Verify every link and build in a real browser before handing over; open the PDF when anything looks wrong.
- Keep the big picture: publication safeguards and learning paths matter more than paper counts.
- Credentials: he may paste a key in chat; you still do not write it anywhere — give him the one-line command instead.

## 10. Adjudicator agent brief (verbatim from the Mac workflow)

Give one Fable-class agent per paper: the pages under `tmp/tx/<id>/pages/`, the three candidates (`.figs.json` variants),
the three checker files, the old Opus JSON as a non-gold reference when it exists, and the instructions in
`scripts/tx/prompts/v1/adjudicator.md` through `task.mjs --stage adjudicator`. Require: gold JSON that validates; the
adjudication JSON with every candidate's defects (path, severity, kind, printed-vs-candidate) and a true/false-positive
verdict for every checker finding; escalations for unreadable spots; no edits to candidates or checks; no gatsby; no git.
Return `{paperId, basedOn, candidates:[{view, verdict, critical, major, minor}], checkerTruePositives, checkerFalsePositives,
escalations, goldValid, minutes, notes}`.
