# Редактор

`/editor` работи без отделен GitHub App или Algolia акаунт. Списъкът с ръчно
написаните модули и решения се създава при билда на сайта.

1. Отворете файл чрез „Отвори файл“ или създайте нов модул.
2. Редактирайте съдържанието и проверете визуализацията. Черновата се запазва в
   този браузър; това не публикува промени в сайта.
3. Използвайте „Копирай“ или „Изтегли“. За модул запазете и двата таба:
   съдържанието `.mdx` и списъка със задачи `.problems.json`.
4. Отворете „Редактирай в GitHub“, поставете съдържанието и прегледайте
   предложената промяна в `OlympiadsXYZ/olympiads-xyz`. За няколко нови файла
   може да използвате връзката „Качи нови файлове в GitHub“.
5. Изпратете промяната за преглед чрез GitHub. Публикуването следва обичайния
   процес за преглед на хранилището.

Изчистването на данните на браузъра премахва локалните чернови. Изтеглете копие,
ако трябва да ги запазите извън този браузър. Презареждането на файл от GitHub
заменя черновата след потвърждение; неуспешно зареждане запазва текущите
редакции.

Генерираните транскрипции се поправят чрез преглед на оригиналния източник, а не
чрез редактиране на генерирания MDX. Използвайте „Съобщи за грешка“ на
страницата на задачата. Формата за предложение на задача подготвя GitHub issue,
което посетителят преглежда и изпраща сам.

Предишният OAuth callback и callable `submitProblemSuggestion` са изключени в
изходния код. Новият сайт не ги извиква. Ако съществува самостоятелно внедрен
Firebase callable, той изисква отделно внедряване на поправката; статичният
Gatsby deploy не внедрява Firebase функции.
